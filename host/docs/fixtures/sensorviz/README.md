# SensorViz Sample Logs

This directory stores curated SQLite logs used to generate SensorViz user-guide
screenshots. SensorViz screenshots should be driven from these `.db3` fixtures
rather than live hardware so menu state, stream lists, and plot contents are
repeatable.

## Maintenance Notes

- Keep these files small enough for source control while preserving the stream
  metadata and enough samples for meaningful plots.
- Prefer logs generated by current `tagcore` SQLite output so SensorViz sees
  the same `streams` metadata users will see in downloaded logs.
- If replacing a fixture, rerun `pragma integrity_check`, record the source
  file, and update the inventory above.
- Do not edit the SQLite tables by hand unless the change is explicitly part of
  a fixture-reduction workflow documented here.

## Screenshot Capture Commands

SensorViz has maintainer-only command-line hooks for loading these fixtures and
writing deterministic PNG screenshots. Use a scratch directory while reviewing
captures, then write final images to `host/docs/src/images`.

```sh
sensorviz --capture-screenshot startup \
  --screenshot-dir /tmp/sensorviz-shots --no-user-prompts
```

```sh
sensorviz --load-log host/docs/fixtures/sensorviz/imutag.db3 \
  --capture-suite imutag \
  --screenshot-dir /tmp/sensorviz-shots --no-user-prompts
```

```sh
sensorviz --load-log host/docs/fixtures/sensorviz/compasstag.db3 \
  --capture-suite compasstag \
  --screenshot-dir /tmp/sensorviz-shots --no-user-prompts
```

The currently implemented suites cover full-window plot/File Info captures plus
top-level and plot-context menus. Dialog screenshots are planned separately
because the live dialogs still need to be factored into captureable builders.
