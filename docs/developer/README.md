# Developer Documentation

This directory defines the developer documentation portal. It is separate from
the end-user manuals under `host/docs`, which are packaged with host
applications.

Build from a configured CMake tree:

```sh
cmake --build build-host --target developer_docs
```

The generated browser entry point is:

```text
build-host/docs/developer/site/index.html
```

Useful related targets:

```sh
cmake --build build-host --target developer_docs_stage
cmake --build build-host --target api_docs
cmake --build build-host --target rust_docs
cmake --build build-host --target all_docs
```

`developer_docs_stage` copies every developer document (as listed by
`docs/tools/docs.py list`) from its source location into the build tree under `reference/`. `api_docs` runs Doxygen when
it is available. `developer_docs` builds the MkDocs portal and, when Doxygen is
available, places the API reference under `api/`.

The API reference is several Doxygen runs. `Doxyfile.in` covers the libraries
and firmware and writes `api/`, plus a tag file. `Doxyfile-app.in` is
configured once per entry in `DEVELOPER_DOXYGEN_APPS` (top-level
`CMakeLists.txt`) and writes `api/<name>/`, linking library symbols back to
`api/` through that tag file. The applications are separate because several
define classes of the same name (`MainWindow`, `LogWindow`). Each application
has a placeholder `src/api/<name>/index.md`, so the portal's navigation and
links resolve, which Doxygen overwrites. To add an application, add an entry,
a placeholder, and a line in `src/api.md` and the `nav:` of `mkdocs.yml`.
Warnings go to `developer-doxygen-warnings.log` and
`developer-doxygen-<name>-warnings.log` in the build's `docs/` directory.

The Rust reference is rustdoc, under `rust/`, listed on the portal's
[Rust Reference](src/rust.md) page. `rust_docs` runs `cargo doc` once per
entry in `DEVELOPER_RUST_DOCS` (top-level `CMakeLists.txt`), all into one
target directory, so the crates share one search and link to one another, and
`developer_docs` runs it after MkDocs when `cargo` is found. To add a crate,
add an entry -- with the path dependencies its links should reach -- and a row
in `src/rust.md`. The Tauri shells are deliberately not documented there.

## Published GitHub Pages

The `.github/workflows/docs.yml` workflow builds the combined repository
documentation site through the CMake `all_docs` target. Pull requests build the
site as a check. Pushes to `main` and manual workflow runs publish a GitHub
Pages artifact with:

- `user/`: the host user guide built from `host/docs`;
- `developer/`: this developer portal built from `docs/developer`;
- a root documentation hub that keeps the external project page linked.

Adding a document to the portal needs only its front matter: the staging list
and the sidebar are generated by `docs/tools/docs.py`. See
[the documentation guide](../documentation-guide.md).
